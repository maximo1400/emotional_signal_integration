# Layer 3: VA Data Adaptation & Output

L3 is the final stage of the emotional signal integration pipeline. It receives the raw predictions generated by Layer 2 and is responsible for temporal smoothing and broadcasting the results to external consumers.

## Structure

- `run.py` — The main execution script for L3. It manages the queue consumption from L2, applies the configured smoothing logic, and handles the network socket broadcasting.
- `smoother.py` — Contains the `DataSmoother` class which implements the different temporal smoothing algorithms.

## Smoothing Algorithms

Since EEG-based emotion prediction can be noisy, L3 applies temporal smoothing to Valence and Arousal outputs. The method is selected via `smoothing_method` in `config.yml`:

- `rolling_buffer`: Uses a simple moving average over the last N frames.
- `ema`: Exponential Moving Average. Smooths the data using an alpha factor (lower alpha = more smoothing).
- `steps`: Confines jumps to discrete step sizes, preventing wild swings in predicted classes.
- `none`: Passes the raw L2 predictions through unaltered.

## Socket Broadcasting

L3 acts as a server that broadcasts the final prediction payloads as newline-delimited JSON. External applications (like Unity, Max/MSP, or custom dashboards) can connect to this socket to consume real-time emotional state data.

Example payload sent over the socket:
```json
{
  "valence": 0.11,
  "arousal": -0.43,
  "confidence": 0.78,
  "timestamp": 1680000000.0
}
```

The network configuration (host, port, protocol) is fully customizable in the `socket_config` section of `config.yml`.

By default L3 expecets a listener to connect to it using TCP. You can change the host, port, and protocol in `config.yml` as needed or deactivate the listener if external one is used.
